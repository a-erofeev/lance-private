# Native-layer ideas for Lance I/O performance

This review compares the native layer at `6d50a6537` with the Lance checkout at
`5ba577117`. It examines implemented code in both projects. The native-layer
design documents describe some planned work and an older baseline, so the code
is the source of truth for current behavior. No cross-project performance
benchmark was run. Possible gains below are hypotheses, not measured results.

## Read path

| Native-layer design | Lance status | Assessment and next step |
| --- | --- | --- |
| **Bounded file workers and batch channels.** A scan starts up to `task_lookahead` per-file workers and sends batches through bounded channels. The workers share a Tokio runtime; the read path does not implement separate I/O and CPU queues. ([worker scheduling](../native-layer/native-layer-rust/src/reader/handle.rs), [channel limits](../native-layer/native-layer-rust/src/reader/stream.rs)) | **Already largely present.** Lance has a priority I/O scheduler with byte-based backpressure and request coalescing. Scans separately limit fragment opens and concurrent batch decoding. ([scheduler](../../lance/rust/lance-io/src/scheduler.rs), [scan](../../lance/rust/lance/src/io/exec/scan.rs)) | Adding two general-purpose queues would duplicate existing controls. Profile scheduler occupancy, decode time, and batch memory before changing scheduling. |
| **Order predicates by read cost.** The native Parquet reader estimates each predicate's cost from compressed sizes of its columns over surviving row groups, then evaluates cheaper predicates first. ([predicate ordering](../native-layer/native-layer-rust/src/reader/pipeline.rs)) | **Potential gap.** Lance's current filtered read adds all filter columns to the initial projection and evaluates the filter after that read. Its legacy pushdown scan also reads the filter columns before evaluation. ([filtered read](../../lance/rust/lance/src/io/exec/filtered_read.rs), [legacy pushdown](../../lance/rust/lance/src/io/exec/pushdown_scan.rs)) | Test staged reads for independent, selective `AND` predicates on costly columns: read one predicate's columns, evaluate it, then fetch later predicate columns only for surviving rows. Sorting the expression alone cannot reduce I/O. Extra requests may outweigh saved bytes on cloud storage. Preserve exact filter semantics, row order, and deletion handling. **Highest-priority read experiment.** |
| **Keep expensive decode away from I/O scheduling.** The native layer's bounded producers expose a possible CPU/I/O scheduling issue, although they do not use a dedicated decode queue. ([pipeline](../native-layer/native-layer-rust/src/reader/pipeline.rs)) | **Partial separation.** Lance has a dedicated `spawn_cpu` pool, but its batch materialization can run synchronous `decode()` inside a Tokio task. ([decode dispatch](../../lance/rust/lance-encoding/src/decoder.rs), [CPU pool contract](../../lance/rust/lance-core/src/utils/tokio.rs)) | Profile large or compression-heavy batches under I/O load. If decode delays I/O tasks, compare dispatching only substantial, pure CPU work to `spawn_cpu`. Keep all waits and I/O outside the CPU closure; dispatch overhead can hurt small batches. |
| **Footer prefetch and metadata reuse.** The native reader prefetches the file tail and caches parsed Parquet metadata. ([reader cache](../native-layer/native-layer-rust/src/reader/cache.rs)) | **Already present in a format-specific form.** Lance reads a tail block, reuses ranges within it, and has a bounded session metadata cache. ([tail read](../../lance/rust/lance-file/src/reader.rs), [session cache](../../lance/rust/lance/src/session.rs)) | Tune tail read size only if traces show repeated metadata round trips. Measure cold and warm opens separately. |
| **Prune early and defer payload reads.** The native reader applies row-group statistics, Bloom and page-index pruning, then uses Parquet row filters before decoding the projected payload. ([pipeline](../native-layer/native-layer-rust/src/reader/pipeline.rs)) | **Concept already present.** Lance uses page statistics and index results to avoid reads, and chooses early or late materialization of non-filter columns. ([pushdown scan](../../lance/rust/lance/src/io/exec/pushdown_scan.rs), [materialization heuristic](../../lance/rust/lance/src/dataset/scanner.rs)) | Do not port Parquet-specific pruning code. The staged-filter experiment above is the useful remaining question for Lance's current format. |

## Write path

| Native-layer design | Lance status | Assessment and next step |
| --- | --- | --- |
| **Account for buffered write memory.** Before an incoming batch reaches `AsyncArrowWriter`, the native writer reserves estimated memory. It resizes the reservation after the write to reflect the reported in-progress buffer size. ([reservation](../native-layer/native-layer-rust/src/writer/mod.rs), [batch handling](../native-layer/native-layer-rust/src/writer/batch.rs)) | **Potential gap at this boundary.** Lance limits page bytes and per-column cache bytes, can spill page metadata, and starts CPU page-encoding tasks before writing their results in order. The reviewed encoding-to-sink path does not show a shared byte admission limit across concurrent writers. ([writer options](../../lance/rust/lance-file/src/writer/structural.rs), [page encoding](../../lance/rust/lance-encoding/src/encodings/logical/primitive.rs)) | Measure peak RSS and throughput with wide batches, compression, and many concurrent writers. If in-flight encoded pages dominate memory, test byte-based admission across encoding tasks or writers. Avoid throttling enough to leave the sink idle. **Highest-priority write experiment, conditional on a memory bottleneck.** |
| **Size output units by bytes.** The native writer estimates uncompressed bytes per row, slices incoming batches, and flushes Parquet row groups near a byte target. ([row-group sizing](../native-layer/native-layer-rust/src/writer/batch.rs)) | **Already present at Lance's own boundaries.** Lance exposes `max_page_bytes` and a soft `max_bytes_per_file` limit. ([page limit](../../lance/rust/lance-file/src/writer/structural.rs), [file limit](../../lance/rust/lance/src/dataset/write.rs)) | Benchmark page and file size settings for target storage and column widths. Parquet row-group logic does not map directly to Lance pages. |
| **Accept Arrow batches natively.** The native Spark path converts `InternalRow` values to Arrow, transfers the arrays through JNI, and writes them as Parquet batches. ([write design](../native_layer_design_rw_full/03_write_path_design.md), [FFI import](../native-layer/native-layer-rust/src/writer/batch.rs)) | **Already present without the row-to-Arrow bridge.** Lance's writer consumes Arrow `RecordBatch` input directly. ([dataset writer](../../lance/rust/lance/src/dataset/write.rs)) | No transfer is needed. Spark row conversion and JNI are costs specific to the native-layer integration. |
| **Return file metadata at close.** The native writer serializes Parquet footer metadata; Java parses it again to derive Iceberg metrics. ([close](../native-layer/native-layer-rust/src/writer/mod.rs), [write design](../native_layer_design_rw_full/03_write_path_design.md)) | **Already simpler.** Lance returns row count and file size from its file writer and attaches them to the data-file descriptor. ([file summary](../../lance/rust/lance-file/src/versions/v2_3/writer.rs), [dataset result](../../lance/rust/lance/src/dataset/write.rs)) | No Parquet footer or Iceberg metrics behavior should be ported. Parquet Bloom, dictionary, and delta encoding options are also format-specific. |

## How to validate the candidates

Use the same Lance files, queries, storage, cache state, and result materialization
for each baseline and variant. For staged filters, vary predicate selectivity,
filter-column width, storage latency, and local versus cloud storage. Record
wall time, bytes read, I/O requests, CPU time, and peak memory. For CPU decode
placement, add a workload with competing I/O and compare tail latency as well
as throughput. For write admission, vary concurrent writers, batch width, and
compression; record sink idle time, throughput, and peak RSS. Keep experiments
on current-format write and read paths; Lance's stable file formats remain a
compatibility contract.
